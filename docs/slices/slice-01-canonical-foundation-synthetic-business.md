# Slice 1 — Canonical ERP Foundation & Synthetic Business

## 1. Objective
Create the complete canonical analytical data foundation for the six-domain MVP and populate it with deterministic synthetic business scenarios and independently reviewable ground truth.

## 2. Dependencies
Slice 0 accepted.

## 3. Scope
- Implement the physical canonical ERP schema and migrations required by Sales, Customers, Inventory, Purchases, Payroll Analytics and Accounting Lite.
- Freeze business-period, currency, timezone, unit, status and identifier conventions needed by the MVP.
- Implement repository/data-access foundations needed to seed and validate data, without building analytical services yet.
- Create deterministic synthetic-data generation using a fixed seed and explicit scenario injection.
- Create seed/reset workflow for PostgreSQL.
- Encode scenarios S1–S8 from `docs/DATA.md`.
- Create independently maintained ground-truth artifacts under `data/ground_truth/`.
- Add data-quality/integrity validation.

## 4. Out of scope
- Analytical domain services and business KPIs beyond data-validation calculations.
- Typed LLM tools.
- LangGraph/OpenAI/LangSmith.
- User-facing analysis API beyond infrastructure endpoints.
- Frontend.
- Real ERP mappings/adapters or MCP.

## 5. Files and components affected
- `migrations/`
- `backend/app/db/`
- `backend/app/repositories/` foundations
- canonical data schemas/models
- `scripts/generate_synthetic_data.py`
- `scripts/seed_database.py`
- `data/synthetic/`
- `data/ground_truth/`
- unit/integration tests for schema, seed and data-quality rules

Domain directories may gain model contracts required by the canonical schema, but analytical services remain for later slices.

## 6. Data / contracts
Mandatory canonical entities from `DATA.md`:
- Customer, Product, Salesperson
- SalesDocument, SalesDocumentLine
- InventoryMovement, StockBalance
- Supplier, PurchaseOrder, PurchaseOrderLine
- GoodsReceipt and helper line/fact structure when required
- EmployeePayrollSummary, PayrollConcept, PayrollSummaryLine or equivalent
- CostCenter
- AccountingPeriod, AccountBalance

The physical design must remain ERP-agnostic and use stable business keys plus internal IDs where appropriate.

Ground truth must include expected scenario relationships and expected metrics without deriving them through the same production services later tested.

## 7. Implementation rules
- Use controlled, parameterized database access.
- Avoid proprietary ERP naming.
- Payroll data must support aggregated financial analysis, not individual-sensitive decisioning.
- Accounting Lite uses structured balances/aggregates; no journal automation.
- Synthetic data must be coherent, deterministic and intentionally scenario-driven, not random noise.
- Ground truth is version-controlled and human-reviewable.

## 8. Synthetic scenarios
Implement all mandatory scenarios from `DATA.md`:
1. Sales decline with mixed explanation.
2. Stockout coincidence.
3. Customer-driven decline without stockout.
4. Supplier delay → PO/receipt delay → stockout → sales decline.
5. Purchase-price increase → gross-margin variance.
6. Payroll overtime → operating-expense variance.
7. Stable/growth controls.
8. Insufficient-evidence / unsupported-request controls.

## 9. Required tests
- Migration up/down or equivalent migration lifecycle checks.
- Uniqueness and FK integrity.
- Valid quantities/statuses/period coverage.
- Sales arithmetic consistency.
- PO/receipt consistency.
- Inventory consistency.
- Payroll aggregate consistency.
- Accounting period/account-balance invariants appropriate to Accounting Lite.
- Seed determinism across repeated runs.
- Ground-truth artifacts exist and are not generated by future production services.

## 10. Acceptance criteria
1. Fresh database migrates successfully.
2. Full six-domain synthetic dataset seeds reproducibly.
3. S1–S8 are present and documented.
4. Data-quality suite passes.
5. Ground-truth expected metrics/relationships are independently stored.
6. No analytical service or LLM behavior is implemented.

## 11. Validation commands
Project-equivalent commands must cover:
- database reset/migrate
- synthetic generation/seed
- data-quality validation
- targeted schema/seed integration tests
- full tests/lint/type checks

## 12. Deliverables
A reproducible synthetic canonical ERP with known business stories and trusted ground truth ready for deterministic analytics.

## 13. Definition of Done
A clean database can be created and seeded from scratch with all six domains, all mandatory scenarios and passing integrity/data-quality tests.

## 14. Prohibitions
Do not implement analytical services, tools, graph nodes, prompts or UI. Do not add real ERP schema knowledge.
